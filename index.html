02 // Problem Statement

Why Current Tracking Falls Short

Hyperhidrosis is difficult to track consistently without one central digital tool. Episodes, triggers, and severity quickly get lost across notes, memory, and messages—making it harder to spot patterns or share a clear history with healthcare professionals.

Context Grounding & Recall Comparison

HyperTrack (Firestore + Grounded Gemini 2.5) 100% Grounded
Unstructured Phone Notes / Memory Fragmented (~25%)
Generic Unscoped LLM Query 0% Patient Logs
GAP // 01

Retrospective Recall Bias

Patients are asked to summarise episode frequency and triggers between clinical visits—without a timestamped log, this is largely guesswork.

GAP // 02

Incomplete Patient History

Clinicians end up judging from an incomplete, self-reported history rather than consistent, structured data covering severity and duration.

GAP // 03

Unrecorded Trigger Data

Stress spikes, caffeine intake, physical activity, and ambient temperature/humidity go unrecorded, so recurring patterns stay invisible.

GAP // 04

Generic AI Risk

A general LLM answer about hyperhidrosis in the abstract is not grounded in what the patient actually logged.

03 // System Architecture

How HyperTrack Is Built

A Firebase-first React 19 frontend paired with a thin Python FastAPI layer dedicated purely to grounded AI reasoning.

Authentication & Session Guard Layer

AuthContext & ProtectedRoute

Tracks the authenticated Firebase user session across the React 19 application and guards all private patient routes. Unauthenticated requests are automatically redirected to /login so patient logs remain strictly private.

• Firebase Authentication (Email / Password provider)
• Automatic route protection via React Router 7

// Session State & Route Protection Flow
1. User submits credentials -> Firebase signIn()
2. AuthContext updates currentUser state
3. ProtectedRoute verifies active session token
4. Grants access to Dashboard, LogEpisode & AI Chat

04 // Testing & Engineering Audit

Key Findings & Stage-2 Roadmap

Every prototype issue below is reported transparently rather than left to be discovered during evaluation.

01 Stage 2 Priority

Static Placeholder Metric

BEFORE: The Dashboard's "AI Pattern Intelligence" card shows a hardcoded 94.2% confidence figure that is not computed from real data.
AFTER: Flagged honestly rather than hidden—genuinely computing or removing it is the first item on the Stage-2 roadmap.
02 Resolved

Firestore Query Drift

BEFORE: Firestore reads were at risk of duplication per page; a mismatch in query shape silently produces an empty or wrong dashboard.
AFTER: Centralised all Firestore access in a single services/episodes.ts module so every view shares one query shape.
03 Verification

Manual-Only Testing

BEFORE: No automated test suite for frontend or backend yet—every screen (Login through AI Chat) is exercised by hand.
AFTER: A backend smoke script confirms /api/ai/insights returns a well-formed 200; a full pytest + unit suite and server-side CSV/PDF export are scoped next.
